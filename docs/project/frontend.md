# Frontend

React, TypeScript и Vite. Интерфейс обращается к реальному API через `/api`; Vite проксирует запросы к локальному backend. Данные, права и состояние доставки определяет сервер.

## Дизайн-код

Светлая рабочая консоль: спокойный фон, белые поверхности и синий акцент для основных действий и ссылок. Шрифт system-ui, основной текст 14/20 px, сетка отступов 4 px, базовый радиус 8 px.

| Токен | Значение | Назначение |
| --- | --- | --- |
| `--color-background` | `#F5F7FA` | Фон страницы |
| `--color-surface` | `#FFFFFF` | Поверхности и поля |
| `--color-text` | `#172033` | Основной текст |
| `--color-muted` | `#475569` | Вторичный текст |
| `--color-border` | `#CBD5E1` | Границы |
| `--color-accent` | `#1D4ED8` | Основное действие и ссылки |
| `--color-success`, `--color-success-bg` | `#166534`, `#F0FDF4` | Успешный результат |
| `--color-danger`, `--color-danger-bg` | `#991B1B`, `#FEF2F2` | Ошибка или проблема |
| `--space-1` … `--space-8` | 4–32 px | Сетка отступов |
| `--radius` | 8 px | Базовый радиус |
| `--control-height` | 40 px | Минимальная высота поля или кнопки |

Доставка и исполнение отображаются отдельными текстовыми метками. Зелёный обозначает подтверждённый успех, красный — ошибку или проблему, нейтральный — ожидание или отсутствие данных. Цвет не является единственным носителем смысла. Поля подписаны, ошибки и загрузка объявляются пользователю, фокус виден с клавиатуры.

## Адаптивность и модули

На широком экране реестр — таблица; при ширине до 700 px те же данные и действия показываются карточками. Фильтр и навигация по страницам общие. Страница и карточка не требуют горизонтальной прокрутки при ширине 390 px.

`src/styles/` — единственное место CSS и визуальных значений: `colors.css`, `typography.css`, `spacing.css` содержат токены; `base.css`, `components.css` и `layout.css` — правила с использованием переменных. `components/` содержит форму входа, форму создания, фильтры, реестр, карточку, панель сверки и общие метки статусов; `api.ts` описывает запросы и ошибки, `types.ts` — контракты, `App.tsx` собирает сценарии. JSX `style`, CSS-in-JS, `element.style` и визуальные константы в компонентах запрещены; правило ESLint проверяется командой `npm run test:styles`.

Ключ создания сохраняется при повторной отправке того же незавершённого запроса; ключ восстановления — при повторе команды для одного сбоя в текущем сеансе интерфейса. После нового события сбоя формируется новый ключ.

При выходе рабочее состояние уничтожается вместе с компонентом сессии. Ответы и ошибки старой сессии, а также устаревших запросов списка и карточки игнорируются. Длинные названия переносятся в карточках и таблице; браузерные тесты `npm run test:session` проверяют задержанные ответы, сетевые повторы и ширину 390/1440 px.
