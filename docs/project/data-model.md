# Модель данных

Flyway применяет миграции из `backend/src/main/resources/db/migration/` при запуске API. Основная схема `public` содержит:

| Таблица | Содержание |
| --- | --- |
| `tasks` | Владелец, заголовок, ключ и хэш запроса, бизнес-статус и версия результата; отдельно ответственный и локальная версия назначения. |
| `outbox` | Состояние доставки, число и лимит попыток, время повтора, срок и токен захвата, причина и признак запланированного восстановления. |
| `exchange_events` | История событий задания: объект, actor, время и непустой структурированный `details` JSONB. V9 восстанавливает поля из надёжных старых источников; недоступные payload-поля помечаются явно. |
| `result_conflicts` | Номер попытки, версии и статусы противоречивых результатов и причина. |
| `operator_scope` | Пары оператора и доступного владельца. |
| `reconciliations` | Локальный и внешний снимки, исход, автор и решение; ошибочный ответ хранится в `bytea`. |
| `recovery_commands` | Ключ ручного восстановления в области оператора и соответствующее задание. |
| `assignment_audit` | Автор, время, прежний и новый ответственный и версии назначения. |

Эмулятор создаёт собственные `executor.executions` и `executor.fault_modes`. Запись исполнения уникальна по `operationId`; счётчик ограничен единицей. Демонстрационные пользователи заданы в серверной конфигурации, а не в таблице пользователей. Время хранится в `timestamptz`, отображается в UTC.

Транзакционные границы и потоки — в [архитектуре](architecture.md), HTTP-контракты — в [API](api.md). V8 добавляет поле деталей, V9 заполняет его из проверяемых источников и запрещает пустые детали новых событий.
