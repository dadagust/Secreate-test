Система принимает задания инициаторов, надёжно доставляет их локальному эмулятору и позволяет оператору разбирать расхождения. Команды запуска Windows, Linux и Docker собраны в README; штатный воркер обрабатывает до 16 записей за тик и прекращает новые захваты после прерывания потока, сохраняя текущую попытку через lease/retry.

## Предсдаточная сверка профиля и seed

Последний стандартный NF08 выполнен 2026-11-12 на 5000 фикстурах, 20 клиентах, с прогревом 30 с, измерением 120 с, polling 1000 мс, batch 16 и суммарными квотами 2 CPU/4096 MiB. После обновления audit fixtures валидатор подтвердил 3218/3218 HTTP 200, p95 чтений 1186,4 мс, p95 изменений 1207,9 мс, 0 ошибок и бизнес-отказов. В измерении создано 806 заданий; 403 внешне исполнены на границе, оставшиеся 403 завершены за drain 51,911 с; итоговая очередь 0. Внешний p95 — 57 869,6 мс (n=806), измерение без SLA-порога. Полный отчёт и JSON: docs/project/performance.md и docs/project/nf08-task-001-03-2026-11-12.json. Предыдущие валидные отчёты сохранены.

Демозаписи определяются стабильными ключами `secreate-demo-v1-<slug>`, а не совпадением владельца и заголовка; режим эмулятора фиксируется до idempotent POST. Регрессии проверяются командами `node --test scripts/demo-seed-identity.test.mjs scripts/performance/nf08-profile-validation.test.mjs scripts/performance/nf08-counts.test.mjs` и `& .\scripts\check-demo-seed.ps1` на изолированном Compose project.

## Аудит изменений NF05

Миграция V8 добавляет JSONB `details` к `exchange_events`, а V9 заполняет исторические события по sequence из внешнего ledger, сохранённых снимков сверки, конфликтов и команд восстановления. Только проверяемые значения восстанавливаются; если payload отсутствует, `legacyPayloadAvailable=false` и причина помечают утрату, без подстановки текущего статуса. Новые переходы результата/доставки, операторские решения сверки и восстановление атомарно сохраняют объект, автора, время, старые/новые значения, версии и причину. Операторская карточка показывает историю; API проверяет роль и `operator_scope`. Ограничение `exchange_events_details_non_empty` запрещает новые пустые события; NF08 fixtures вставляют полные details.

## Предсдаточные регрессии

DeliveryWorker проверяет interrupt перед каждым захватом. Если поток прерван во время HTTP, текущая попытка записывается через штатную lease/retry-семантику, флаг восстанавливается, а следующие записи остаются незахваченными до нового тика. PostgreSQL-регрессии для прерывания до claim и во время HTTP включены в Maven verify. Для чисто распакованного Linux-архива Maven Wrapper запускается через `sh ./mvnw -B -ntp verify` из `backend/`; PowerShell использует `.\mvnw.cmd`.
