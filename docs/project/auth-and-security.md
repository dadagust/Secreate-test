# Аутентификация и безопасность

Для локальной демонстрации `Security` использует HTTP Basic и статический `InMemoryUserDetailsManager`: Alice и Bob имеют роль INITIATOR, operator — OPERATOR. Пароли и команды входа приведены в корневом README. Сессия сервера stateless, CSRF отключён; эта конфигурация предназначена для локального демо.

Frontend хранит credentials успешного demo-входа в `sessionStorage` текущей вкладки, чтобы восстановить экран после reload; logout очищает их. Так как HTTP Basic требует пароль на каждом запросе, это не заменяет защищённую серверную сессию и не предназначено для production.

Создание задания разрешено только INITIATOR. Операторские маршруты и назначение ответственного требуют OPERATOR; доступ к отдельному заданию дополнительно проверяется по `operator_scope`. Инициатор получает только свои задания. Эти проверки выполняются на сервере, а не только в интерфейсе. Эмулятор и его команды режимов не имеют аутентификации; опубликованные локальные порты Compose привязаны к loopback.

Проверки прав на PostgreSQL перечислены в [матрице приёмки](acceptance.md). Промышленная идентификация, управление пользователями и защищённое удалённое развёртывание в демо не реализованы.
