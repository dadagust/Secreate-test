# Конфигурация

Backend читает `SPRING_DATASOURCE_URL`, `SPRING_DATASOURCE_USERNAME`, `SPRING_DATASOURCE_PASSWORD` и `EXCHANGE_EXECUTOR`. По умолчанию адрес исполнителя — `http://localhost:9090`. Воркер включён по умолчанию; `EXCHANGE_WORKER_ENABLED` управляет его запуском, `EXCHANGE_WORKER_FIXED_DELAY_MS` задаёт задержку после тика (по умолчанию 1000 мс), а `EXCHANGE_WORKER_MAX_ITEMS_PER_TICK` ограничивает число последовательных доставок в одном тике (по умолчанию 16, допустимо 1–256).

Эмулятор использует `EXECUTOR_DB_URL`, `EXECUTOR_DB_USER`, `EXECUTOR_DB_PASSWORD` и `EXECUTOR_BIND_ADDRESS` (по умолчанию `127.0.0.1`). Команды управления режимами не аутентифицированы и предназначены для локальной демонстрации. Данные и демонстрационные пароли в примерах запуска не предназначены для промышленного использования.

Обычный `compose.yaml` запускает PostgreSQL с именованным томом и публикует его на loopback-порту 5432; `POSTGRES_PUBLISHED_PORT` позволяет выбрать другой порт. `compose.performance.yaml` дополняет его сервисами и ресурсными лимитами для профиля NF08. По умолчанию он использует ту же конфигурацию worker, что и приложение (1000 мс и 16 записей за тик); экспериментальный интервал можно задать через `NF08_WORKER_POLL_MS`. Исторические прогоны с 50 мс остаются отдельными данными и не являются результатом штатного интервала. Результаты профилей и их область применимости — в [отчёте](performance.md).

`compose.app.yaml` отдельно собирает и запускает PostgreSQL, API, эмулятор и frontend с nginx-прокси. `APP_FRONTEND_PORT`, `APP_API_PORT` и `APP_EMULATOR_PORT` меняют опубликованные loopback-порты; `POSTGRES_PASSWORD` задаёт пароль при первичном создании тома. PostgreSQL не публикуется на хосте. Одноразовый сервис `seed` вынесен в отдельный профиль: обычный рестарт сервисов его не запускает. Команды полного демо приведены в корневом README.
