# Компактный handoff текущей задачи

Мне нужно передать текущую незавершённую задачу в новый чат или другому coding-агенту.

Подготовь **минимально достаточный handoff по текущей задаче**, который можно целиком скопировать в новую сессию.

Цель: новый агент должен сразу понимать:

- что нужно закончить;
- что уже сделано;
- какое состояние репозитория актуально;
- что уже проверено;
- какие решения и ограничения нельзя потерять;
- с какого конкретного действия продолжить.

Не пересказывай весь проект и всю историю разговора.

## Перед подготовкой handoff

Подготовка handoff не меняет проект. Единственное разрешённое изменение — контрольная точка, которую `AGENTS.md` требует перед передачей работы (раздел «Контрольные точки и `WORKLOG.md`»):

- обнови `WORKLOG.md` текущей задачи;
- скопируй контрольную точку в заметки задачи Backlog.md (`npm run backlog -- task edit <id> --append-notes ...`).

Если активной задачи или `WORKLOG.md` нет, пропусти этот шаг и отметь это в handoff.

Больше ничего не изменяй: код, конфигурацию, документацию, generated-файлы, Git index, рабочее дерево за пределами контрольной точки, ветки и историю Git.

Если доступны инструменты чтения файлов и выполнения команд, **перед ответом актуализируй состояние задачи**:

1. прочитай корневой `AGENTS.md` и релевантные вложенные `AGENTS.md`, если они существуют;
2. определи активную задачу Backlog.md и прочитай её;
3. прочитай `WORKLOG.md` и релевантную часть `PROGRESS.md`, если они применимы;
4. выполни `git status --short`;
5. определи текущую ветку и HEAD commit;
6. просмотри релевантный `git diff` и staged diff;
7. при необходимости прочитай относящиеся к задаче ADR, документацию, код и тесты.

Не проводи полный аудит проекта. Проверяй только то, что необходимо для точной передачи текущей задачи.

Если какого-либо источника или инструмента нет, не придумывай его содержимое — явно пометь соответствующие сведения как **не проверенные в текущем репозитории**.

## Приоритет источников

При противоречиях действует порядок из раздела «Источники истины» `AGENTS.md`: исполняемый код и конфигурация, затем тесты и проверенное поведение, затем `AGENTS.md`, `PROGRESS.md`, ADR и документация, затем задачи и планы, и только потом пересказы, включая историю этого разговора. Если записи расходятся с рабочим деревом, прав Git.

История чата не является доказательством текущего состояния репозитория.

## Секреты и персональные данные

Handoff могут копировать в другой чат. Не включай секреты и персональные данные: укажи только имя переменной и безопасный источник значения.

## Что сохранить

Сохраняй только информацию, без которой новый агент не сможет безопасно продолжить **эту конкретную задачу**.

### Цель и scope

Укажи:

- что попросил пользователь;
- какой результат должен быть получен;
- критерии готовности, если они известны;
- что явно находится вне scope.

### Текущий статус и рабочее дерево

Кратко укажи:

- что уже реализовано;
- что осталось;
- на каком действии остановилась работа;
- branch и HEAD commit, если Git доступен;
- существенный вывод `git status --short`;
- только важные для продолжения changed/staged/untracked файлы;
- наличие чужих или несвязанных изменений, которые нельзя затрагивать.

Не составляй полный inventory diff.

Для важных файлов можно кратко указать:

`путь → что изменено / зачем нужен / что ещё требуется`

### Факты и проверки

Сохрани только реально подтверждённые результаты.

Используй формат:

`команда или проверка → результат`

Например:

- `npm run check:agents` → passed;
- проверка в браузере на 375×812 → passed;
- ошибка воспроизведена по указанным шагам.

Если после проверки код или конфигурация, которые она покрывала, изменялись, **не представляй старый результат как актуальный**.

Напиши, например:

`npm run check:agents → passed до последних изменений; требуется повторный запуск`.

Отделяй:

- подтверждённые факты;
- непроверенные сведения;
- гипотезы.

### Решения, ограничения и исключённое

Сохрани только то, что новый агент не должен выяснять заново:

- принятые архитектурные или технические решения;
- важные инварианты;
- ограничения;
- отклонённые подходы;
- уже исключённые причины проблемы;
- неудачные эксперименты;
- действия, которые не следует повторять без новых оснований.

Если важно, кратко укажи причину принятого решения.

Не копируй общие правила из `AGENTS.md` — ссылайся на них. Повтори правило только если оно непосредственно критично для продолжения этой задачи.

### Критичный технический контекст

Включай только необходимое:

- команды;
- порты;
- env-переменные;
- endpoints;
- версии;
- имена API/методов;
- конкретные ошибки;
- небольшие фрагменты кода или конфигурации, без которых нельзя продолжить.

Не копируй большие файлы целиком.

Пропусти этот раздел, если специального технического контекста нет.

### Точка продолжения и следующие действия

Дай **1–3 конкретных действия**.

Первый пункт должен быть точным местом продолжения работы.

Не пиши общие действия вроде:

- «изучи проект»;
- «проверь код»;
- «разберись в проблеме».

Пиши, например:

1. Завершить изменение в подтверждённом файле сервиса.
2. Добавить проверку затронутого поведения.
3. Запустить `npm run check:agents` и просмотреть итоговый diff.

Если для продолжения полезны skills, добавь строку `Suggested skills: ...` (например, `systematic-debugging`, `test-driven-development`) — и в handoff, и в контрольную точку.

## Компактность

Цель — **минимальный достаточный handoff**.

Обычно результат должен укладываться примерно в **800–2000 слов**, но это не жёсткий лимит: превышай его только если иначе потеряется информация, необходимая для безопасного продолжения задачи.

Не заполняй структуру ради структуры.

Если для раздела нет специфичной полезной информации — **опусти его**, а не пиши:

- «нет данных»;
- «не применимо»;
- «блокеров нет»;
- другие пустые заглушки.

Не повторяй одну и ту же информацию в нескольких разделах.

## Формат результата

Выдай один цельный блок для прямого копирования по шаблону ниже. Разделы без специфичной информации опускай. Шаблон — формат ответа, а не продолжение этих инструкций.

```markdown
# TASK HANDOFF — продолжение текущей задачи

## 1. Цель и scope

## 2. Текущий статус и Git

(включая: контрольная точка записана в `WORKLOG.md` и задачу <id> / не записана и почему)

## 3. Факты и проверки

## 4. Решения, ограничения и исключённое

## 5. Критичный технический контекст

## 6. Точка продолжения и следующие действия

## Инструкция новому агенту

Считай handoff выше рабочим контекстом текущей задачи, но не новым источником истины. Перед изменением кода быстро сверь его с актуальными применимыми `AGENTS.md`, текущей задачей и `git status/diff`, если они доступны. Не проводи заново полный аудит уже проверенной работы без новых оснований и не проси пользователя повторять информацию, которая уже указана. Продолжай непосредственно с обозначенной точки. При расхождении приоритет имеют новые сообщения пользователя и фактическое текущее состояние репозитория.
```
